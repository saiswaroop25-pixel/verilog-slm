# Pinned per Part 0 hygiene notes: Colab silently upgrades packages
# between sessions and transformers breaks LoRA loading regularly.
#
# Core deps (data pipeline, verify harness, eval metrics) are CPU-only and
# runnable anywhere. Train/infer deps pull in the CUDA stack and are only
# needed on the Colab GPU runtime -- install with:
#   pip install -r requirements.txt -r requirements-train.txt
#
# numpy is intentionally NOT exact-pinned. An exact pin here forces pip to
# downgrade whatever numpy Colab's image already ships (numpy 2.x), and
# every other preinstalled package with compiled C extensions (pandas,
# pyarrow, scipy -- pulled in transitively by `datasets`) was built against
# THAT numpy's ABI. Downgrading numpy out from under them is exactly what
# produced: "ValueError: numpy.dtype size changed, may indicate binary
# incompatibility. Expected 96 from C header, got 88 from PyObject" the
# first time this was hit. A minimum-version floor is enough for the numpy
# API this repo actually uses (RandomState, percentile, prod, arange --
# all stable across 1.x/2.x); it doesn't force pip to touch numpy at all
# when Colab's preinstalled version already satisfies it.
pyyaml==6.0.2
numpy>=1.24
datasketch==1.6.5
pyverilog==1.3.0
pytest==8.3.3
